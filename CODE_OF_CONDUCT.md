# Code of Conduct

## The short version

Be direct, be kind, be technically honest.

Disagreement on technical or strategic decisions is welcome and expected. Disagreement
about whether someone deserves to be in the room is not.

## What we expect

- **Technical honesty.** Don't overclaim, don't hide limitations, don't engage in bad
  faith. "I was wrong" and "I don't know" are good things to say here.
- **Directness with respect.** Critique ideas, code, and claims as hard as you like —
  but attack the work, never the person.
- **Good faith.** Assume contributors are trying to help. Ask before assuming malice.
- **Inclusion.** Everyone is welcome regardless of age, origin, identity, background,
  or experience level. Newcomers asking "basic" questions are doing exactly the right
  thing.

## What is not acceptable

- Personal attacks, insults, or demeaning comments.
- Harassment of any kind, public or private.
- Discrimination or exclusionary behaviour.
- Publishing others' private information without permission.
- Sustained bad-faith engagement (e.g. trolling, deliberate derailing).

## Scope

This applies to all project spaces — the repository (issues, pull requests, discussions,
commit messages), and any public space where someone is representing the project.

## Reporting and enforcement

This is currently a single-maintainer project. If something happens that needs handling
privately, email **`qrb.grants@proton.me`**. Reports will be handled discreetly.

The maintainer may take any action deemed appropriate, from a private warning to
removing comments, commits, or contributions, up to banning a contributor from project
spaces. Decisions will be explained where doing so doesn't compromise someone's privacy.

## Attribution

This Code of Conduct reflects the project's own values and is informed by the spirit of
the [Contributor Covenant](https://www.contributor-covenant.org). It is intentionally
short; if the community grows to a point where a more formal framework is needed, we'll
adopt one openly.
